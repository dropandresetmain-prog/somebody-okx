## 1. Evidence origin (Blocker A)

```ts
// lib/objective/types.ts
export type EvidenceOrigin = "application_observation" | "model_note";
```

- `application_observation` — content was fetched by application code in
  `read_company_record` / `read_public_web`. This is the **only** origin that
  may satisfy proof.
- `model_note` — prose authored by the model (including `record_finding`).
  Persisted for transparency, **never** counts toward proof.

`EvidenceRecord` gains two required fields:

```ts
export type EvidenceRecord = FindingInput & {
  id: string;
  recordedBy: string;
  runId: string;
  origin: EvidenceOrigin;
  sourceId: string;   // stable source identity, see §2
};
```

`FindingInput` also gains `origin` and `sourceId` (required, not optional) so
the Convex validator and the in-memory shape agree.

## 2. Source identity (Blockers A + B)

Stable, deterministic identity of *where* content came from, not of a row:

```ts
// lib/objective/contract.ts — single implementation, imported everywhere
export function sourceIdentity(input: {
  sourceClass: SourceClass;
  url?: string;
  recordRef?: string;
}): string;
```

Rules:
- `company_record` -> `` `record:${recordRef.trim()}` ``
- `public_web`     -> `` `url:${normalizePublicUrl(url)}` ``
- missing identity -> `""` (must never satisfy proof)

`normalizePublicUrl(url: string): string` (exported from `contract.ts`):
lowercase scheme + host, strip `www.` prefix, drop fragment, strip trailing
`/`, keep query. Unparseable URL -> `""`. No network, no dependency.

## 3. Distinct-source proof requirements (Blocker B)

Replace the "any row of that class + raw row count" rule with per-class
**distinct** counts:

```ts
// lib/objective/types.ts — added to WorkContract
export type SourceProof = {
  sourceClass: SourceClass;
  minDistinctSources: number;
};

// WorkContract gains:
sourceProofs: SourceProof[];
```

Keep the existing `requiredSourceClasses` and `minObservations` fields
(derived from `sourceProofs`, unchanged semantics) — the Convex validators,
the read model and the UI already depend on them. `evaluateCompletion` must
gate on `sourceProofs`; the other two stay for display/invariants.

`RESEARCH_ROLE` (policy.ts) becomes:

```ts
sourceProofs: [
  { sourceClass: "company_record", minDistinctSources: 1 },
  { sourceClass: "public_web",     minDistinctSources: 2 },
]
```

so `requiredSourceClasses = ["company_record","public_web"]` and
`minObservations = 3` (sum) stay as they are today.

`createWorkContract` input takes `sourceProofs` and derives
`requiredSourceClasses` + `minObservations`. Keep validating
`minObservations >= requiredSourceClasses.length` behavior.

## 4. `record_finding` semantics (Blocker A)

`record_finding` must NOT mint proof. Two allowed shapes, pick the second:

- it stores `origin: "model_note"` and `sourceId: "note:<evidenceId>"`
  (unique per note, so it can never collides into a real source identity).

A note may reference an existing observation from the same active run via
`basedOnEvidenceId`, so the worker can still annotate real content. The
runtime tool must validate that reference against the current run's
application observations and reject it otherwise.

## 5. Observation surface returned to the worker (Blocker C)

`lib/worker/port.ts` `WorkerObservation.recordedFindings` gains:

```ts
{
  id: string;
  sourceClass: string;
  label: string;
  origin: string;          // "application_observation" | "model_note"
  text: string;            // BOUNDED, untrusted data
  url?: string;
  recordRef?: string;
}
```

- Cap each `text` at **1200** characters, marking truncation with a literal
  `…[truncated]` suffix. Cap the whole `recordedFindings` list at the **6**
  most recent entries.
- `port.act()` must return the bounded observed content for read tools — not
  just a label. Keep the JSON `{ result, observation }` envelope.
- Wrap external/public text so it is unmistakably data. Use exactly this
  marker shape in the text the model sees:

```
<untrusted_content source="public_web" origin="application_observation">
...
</untrusted_content>
```

`company_record` uses `source="company_record"`. Internal records are still
data, not instructions.

## 6. Completion result truthfulness (Blocker F)

The Convex read model must expose, alongside `record`/`evidence`/`events`:

```ts
completion: {
  accepted: boolean;      // application accepted proof, not model claim
  unmet: string[];        // reasons it is not accepted
}
```

UI may label a result "Accepted" **only** when `completion.accepted`.

## 7. Role-capability satisfiability (Blocker D)

Pure helper, owned by Agent B in `lib/objective/planner.ts`:

```ts
export type RoleObservationRequirement = {
  roleKey: string;
  requiredToolPermissions: ToolPermissionId[];
};

export function assertRoleRequirementsSatisfied(input: {
  grantedPermissions: readonly string[];   // validated capability envelope
  role: RoleObservationRequirement;
}): { ok: true } | { ok: false; missing: string[] };
```

RESEARCH_ROLE requires `read_company_record` **and** `read_public_web`.
`document_drafting` alone, or `public_information_research` alone, must fail.
Fails closed: a `missing` result must stop planning before any run starts.

`RESEARCH_ROLE` must therefore also expose:

```ts
requiredToolPermissions: ["read_company_record", "read_public_web", "record_finding"]
```

(Agent A adds this to policy.ts; Agent B consumes it.)

## 8. Run lifecycle budget (Blocker E)

PRIMARY owns all of this — listed here only so lanes stay compatible.

```
EXECUTION_TIMEOUT_MS (270_000) < LEASE_MS (300_000)
```

- `finishRun` finalizes only `status === "running"` runs; otherwise a
  deterministic no-op returning the current truth.
- `assertActiveRun` also requires `leaseUntil > now`.
- `executeRun` passes an `AbortSignal` that fires inside the lease.
